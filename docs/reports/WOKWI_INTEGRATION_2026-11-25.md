# Wokwi ESP32 Integration — 2026-11-25

## Implemented locally

Project: `ingestion/iot/wokwi/esp32-air-quality-node/`

- ESP32 DevKitC V4 circuit and firmware sketch.
- DHT22 for simulated temperature/humidity.
- Three potentiometers for synthetic PM1/PM2.5/PM10 test inputs.
- MQTT status LED.
- Firmware publishes JSON schema v1.0 every 10 seconds.
- Public broker target: `broker.hivemq.com:1883`.
- Local optional bridge: `ingestion/ingestion/iot/wokwi/bridge.py`.
- Compose service: `wokwi-mqtt-bridge`, profile `wokwi`.
- Streamlit can independently start/stop the bridge.

## Network design

The free development path uses Wokwi's public internet gateway to reach a
public MQTT broker. The local bridge subscribes only to a high-entropy topic
prefix from the ignored local `.env`, validates incoming messages, adds
configured Egypt location metadata, and republishes to local Mosquitto.

The local Mosquitto listener is not exposed to the public internet. The public
broker is unauthenticated and plaintext MQTT; the random topic prefix and
payload validation are defense-in-depth only, not a production security
boundary. Do not send secrets or personal data. For production/Azure, replace
this path with authenticated TLS MQTT ingress and proper authorization.

## Data semantics

All Wokwi telemetry is simulated. Potentiometers are not calibrated PM sensors.
DHT22 values are generated by the Wokwi sensor model. The bridge tags records:
- `source=wokwi_esp32`
- `simulation=true`
- `simulation_provider=wokwi`
- `simulation_profile=wokwi-esp32-public-mqtt-v1`
- `particulate_input_model=potentiometer_test_inputs_not_physical_pm_sensor`

The bridge adds `country_code=EG`, governorate and coordinates so Silver's
Egypt bounds checks can be applied. Silver validation explicitly recognizes
Wokwi on Kafka topic `air-quality`. Gold uses the existing non-OpenAQ
measurement aggregation path.

## Acceptance gates

1. Build firmware successfully in Wokwi/PlatformIO.
2. Open the diagram and confirm all component pins/wires render.
3. Copy the topic prefix shown in Streamlit into `TOPIC_PREFIX` in the sketch.
4. Start Wokwi simulation and confirm Wi-Fi/MQTT status in serial output.
5. Start Wokwi ESP32 bridge from Streamlit.
6. Confirm Wokwi telemetry appears in Bronze and is accepted by Silver.
7. Confirm Gold consumes the corresponding Silver batch.
8. Reconcile the exact device ID and source lineage through PostgreSQL.

Keep the Python simulator for multi-device/load testing; Wokwi provides the
embedded firmware and circuit simulation layer.
